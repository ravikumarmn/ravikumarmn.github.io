## Problem

Enterprise knowledge was split between unstructured documents and structured tables. People needed one place to ask questions that span both: analytics questions, document questions, and questions that need a bit of each. The answers had to be grounded in the source data.

## Constraints

- **Mixed sources.** Some questions need semantic recall over documents, some need exact keyword matches, and some need SQL over tables.
- **Grounding.** Answers had to be traceable to retrieved evidence, not invented by the model.
- **Interactive latency.** A copilot people actually use has to answer in seconds, with retrieval taking only a small part of that time.
- **Operability.** Releases needed tracking, evaluation, and versioning so a quality regression could be caught and rolled back.

## Approach

### Plan first, then retrieve

Multi-agent orchestration splits each request into three steps: **query planning**, **data retrieval**, and **response synthesis**. The planner decides which route a question needs: hybrid retrieval, a **SQL agent** for structured data, or **tool calls** for analytics and document workflows.

### Hybrid retrieval across structured and unstructured data

Vector search alone misses exact identifiers and rare terms, and keyword search alone misses paraphrases. I combined **vector and keyword retrieval** across structured and unstructured sources, which improved answer relevance and grounding accuracy. {/* GAP: how much relevance/grounding improved (hit-rate, grounding score, human rating). */} <Verify note="Merge/rank step drawn in the figure is inferred; confirm the fusion method (e.g. reciprocal rank fusion, a reranker).">The two result sets are merged and ranked before synthesis.</Verify>

### Synthesis with memory and guardrails

The synthesis step keeps **contextual memory** across turns and applies **guardrails** before an answer is returned.

### Latency work

I optimized both the inference path and the retrieval path, reaching **1.8s end-to-end** response latency with vector search **under 120ms** at scale. {/* GAP: what changed to get there, and the starting latency. */}

### Shipping

The system is deployed on **Azure** and **Databricks**, with **MLflow** for model tracking, evaluation, and versioned releases.
